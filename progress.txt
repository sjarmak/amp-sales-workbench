## Codebase Patterns
- Product filter: use `is_code_search_opp()` copied from analyze-pipeline-strategy.py -- checks CODE_SEARCH_PRODUCTS set, excludes AMP_CODY_PRODUCTS
- Helper functions: `safe_float()`, `safe_int()`, `parse_bool()`, `fmt_currency()`, `pct()` are standard across all analysis scripts
- JSONL loading: `load_jsonl()` reads line-by-line with `json.loads()`
- Gong calls have NO account_id field -- must match via call title using `extract_company_from_gong_title()` + fuzzy account name matching
- Fiscal years: FY25 = 2024-02-01 to 2025-01-31, FY26 = 2025-02-01 to 2026-01-31 (Sourcegraph fiscal year starts Feb 1)
- Contact roles join to opps via `opp_id` field; leads join to contacts via `email` / `lead_email`
- Notes join to accounts via `account_id` field directly
- Deal size tiers used in project: $0-50K, $50K-200K, $200K+
- Print formatting: `print_header()` for sections, `print_subheader()` for subsections, `print_table()` for aligned tabular output
- `_fiscal_year` and `_iarr` are cached on won_opps dicts as computed fields (prefixed with underscore)
- Contact role field (`opp_contact_role`) is 91% blank -- only ~9% of contacts have roles assigned. Filter out date-like garbage values with a VALID_ROLES allowlist
- Lead title join is sparse: only 5 Economic Buyers and 10 Champions matched via email to leads with titles. The join path works but coverage is low
- Committee sizes: median=1, but $200K+ deals have median=4 and mean=5.6 -- much larger buying committees for enterprise deals
- `_days_to_close` is pre-computed on won_opps via `safe_float(o.get("days_to_close"))` in main()
- Stage dwell fields: `opp_days_stage2_to_stage3` through `opp_days_stage6_to_won` -- only ~70-155 opps have data (10-22% coverage)
- POC dates (`poc_start_date`, `poc_end_date`) are empty for all closed-won opps in this dataset
- `technical_win_achieved` field: 25% of won opps have it set to "true" (string comparison, case-insensitive)
- Renewals dominate cycle time (median 366 days), expansions are fast (median 14 days) -- always segment by opp_type for meaningful velocity stats
- Use a `percentile()` helper for P25/P75 since `statistics` module doesn't have one in stdlib
- Text mining coverage is sparse: only 67/316 won accounts have any notes/gong text, 31 with SCM mentions, 9 with language mentions
- For Go language regex: use negative lookbehind for "let's/let us/lets" and negative lookahead for common verbs ("to", "ahead", "with", etc.) -- case-sensitive match
- For R language regex: require context indicators ("R programming", "R language", "code in R") to avoid false positives from single letter
- `_extract_text_blocks()` helper collects text from both notes (note_text) and gong (spotlight_brief, spotlight_key_points, transcript_text)
- Co-occurrence pairs include SCM-SCM, Lang-Lang, and SCM-Lang combinations
- `products_included` field is semicolon-separated (not comma); some opps with blank products use opp name as fallback
- `_parse_products()` helper splits on ";" and falls back to opp name for blank products_included
- For product bundles, filter to CODE_SEARCH_PRODUCTS set to get meaningful bundle combos (excludes add-ons like Platform Fee, Slack Support)
- Geo and region fields are in `sfdc_account_details.csv`, not in opportunities -- join via `accounts_by_id`
- `_segment_table()` is a reusable inner function that groups opps by any lambda, computes stats, prints table, returns dict
- 81% of won opps have blank primary_use_case; only 13% have any use_case flag set
- `render_bar_chart()` generates inline SVG with horizontal bars; params: data (label/value tuples), title, width, bar_height, color
- `_svg_escape()` handles &, <, >, " for safe text embedding inside SVG `<text>` elements
- SVG charts use viewBox-based sizing for responsiveness; `max-width:100%;height:auto` in inline style
- Chart colors follow report theme: purple (#A112FF) for lead source, orange (#FF8800) for stage dwell, green (#00B265) for competition, cyan (#00CBEC) for products, red (#FF5543) for use cases
